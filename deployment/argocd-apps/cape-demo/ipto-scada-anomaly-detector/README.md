# ipto-scada-anomaly-detector

PostgreSQL for the IPTO SCADA anomaly-detection demo, a Ryax workflow.

The workflow's `dbase` module writes one row per scored parquet entry into
`parquet_entries`. That table is all this app provides — the workflow itself is
imported into Ryax through its UI by the workflow owners and is not deployed from git.

## Connection

```
postgres://postgres:<password>@postgres.ryaxns-tools.svc.cluster.local:5432/parquet_data
```

In-cluster only. No Gateway route, no Ingress: it is a demo database with a fixed
credential and no TLS.

## Before first deploy

```bash
source ./scripts/pulumi/initPulumiStack.sh          # sealSecrets.sh needs the stack
deployment/argocd-apps/cape-demo/ipto-scada-anomaly-detector/sealSecrets.sh
```

⚠ **Nothing is generated**, unlike every other app here. The workflow modules carry the
whole connection string compiled in — user, database and password — so all three must
match what they expect. The script prompts for each, offering the documented value as
the default:

```
  database user [postgres]:
  database name [parquet_data]:
  database password:
```

On a re-run each value is recovered from the sealed file instead, so re-running never
rotates a live credential. For an unattended run, set any or all of
`CAPE_DEMO_PG_USER`, `CAPE_DEMO_PG_DB`, `CAPE_DEMO_PG_PASSWORD`. Pass `--regenerate`
to ignore the sealed file and re-enter everything.

Changing a value breaks the workflow silently — the modules fail at connect time, which
surfaces as a failed Ryax execution rather than as anything naming authentication.

⚠ `POSTGRES_USER` and `POSTGRES_DB` are more than credentials: they are what the
postgres entrypoint **creates** on first start, once, on an empty data directory.
Changing either after the database exists leaves the live cluster untouched and the
workflow pointing at a role or database that was never created — see *Schema changes*
below.

## Placement

Pinned to the lab (`ecc/site=unibi-hclab`) with the `ecc/mesh` toleration, and its
volume comes from `longhorn-unibi-ryax` — the same storage scope the Ryax engine and
its execution pods use.

Both are stated explicitly in `postgres.yaml`. Ryax's `MutatingAdmissionPolicy`, which
injects placement for Ryax's own pods, is scoped to the `ryaxns` / `ryaxns-execs`
namespaces **by name** and does not reach `ryaxns-tools`. Without the toleration the
pod is unschedulable: the only nodes carrying the `unibi-ryax` scope are mesh nodes,
and every mesh node is tainted `ecc/mesh=true:NoSchedule`.

## Schema changes

`postgres-init` runs **once**, on an empty data directory — the postgres entrypoint
executes `/docker-entrypoint-initdb.d` only when `PGDATA` holds no cluster yet.
Editing `init.sql` afterwards does nothing, and ArgoCD reports the app Synced while the
live schema is unchanged. To change a running database, run the SQL by hand:

```bash
kubectl -n ryaxns-tools exec -it deploy/postgres -- psql -U postgres -d parquet_data
```

## Not backed up

`postgres-pvc` is excluded from every Longhorn snapshot and S3 backup job, like the rest
of the CAPE stack. The data is demo output, regenerated by re-running the workflow.

⚠ That exclusion is enforced from **outside this app**, by the PostSync hook in
[../ryax/snapshot-policy.yaml](../ryax/snapshot-policy.yaml), which loops over both
`ryaxns` and `ryaxns-tools`. A deliberate cross-app coupling: it avoids a second
near-identical copy of the hook drifting out of sync. The consequence is that disabling
or deleting the **ryax** app stops the policy being re-applied here too, and this volume
would rejoin `unibi-ryax` on its next reprovision.

The volume keeps 3 replicas — only the Ryax nix build cache drops to 1.

## Not CloudNativePG

Every other database in this cluster is a CNPG `Cluster` with barman S3 backups and
PITR. This one is a plain Deployment because the workflow modules require a fixed
`postgres` superuser credential, and because the data is demo output that is
regenerated by re-running the workflow. There is no backup, by design.

If this ever holds something whose loss matters, convert it — see
`deployment/argocd-apps/rallly/postgres.yaml` for the shape.
