# eda-xilinx-2024-1 — Vivado 2024.1 as a CONTAINER module

Build-only. This app owns the machinery to build and publish the runnable Vivado 2024.1
module image (`deployments/infrastructure/eda/modules/xilinx-2024-1:2024.1`):

- `namespace.yaml` — one namespace per EDA app, named after it
- `postsync-build-image.yaml` — the build trigger (mirror build files → GitLab → pipeline
  on the `[eda]` runner)
- `postsync-register-module.yaml` — re-registers the module after a cluster recreate
- `build-files-configmap.yaml` — Dockerfile + `.gitlab-ci.yml` + `install_config.txt` +
  `module.yaml`, mirrored into GitLab

Its Application is generated by `app-of-apps/eda-modules-appset.yaml`, not by a file of
its own.

## How it runs

Vivado runs **inside the shared remote-desktop pod**: a user runs `module load
xilinx/2024.1` and the desktop's podman runs this image. There is no
desktop/Guacamole/VNC here.

⚠ **Building the image does NOT make it loadable.** The module must also be REGISTERED in
the module registry, which is the broker's authority for what may run. This module
publishes to a NON-DEFAULT repo (`module.yaml`'s `image:` key), so the manifest must be
passed explicitly — `broker register`'s default path would look in `.../modules/vivado`:

```
deployment/argocd-apps/remote-desktop/register-module.sh add xilinx 2024.1 \
  deployment/argocd-apps/eda/xilinx-2024-1/module.yaml
```

Registration is automatic on a recreate via the PostSync Job above; this is for ad-hoc work.

Requires remote-desktop `base-r14+` (`module_image()`/`image:` support in the broker, and
the `$HOME`/CWD bind in the container launcher, without which batch runs cannot do file I/O).

## Installer media

`EXTRACT=/build-scratch/xilinx-2024-1-extracted` holds the extracted 115 GB media. That
tree is **node-local**: `/build-scratch` is a hostPath, so each enrolled runner node pays
its own extraction.
