# eda-xilinx-2026-1 — Xilinx 2026.1 as a CONTAINER module

Build-only. This app owns the machinery to build and publish the runnable Xilinx 2026.1
module image (`deployments/infrastructure/eda/modules/xilinx-2026-1:2026.1`):

- `namespace.yaml` — one namespace per EDA app, named after it
- `postsync-build-image.yaml` — the build trigger (mirror build files → GitLab → pipeline
  on the `[eda]` runner)
- `postsync-register-module.yaml` — re-registers the module after a cluster recreate
- `build-files-configmap.yaml` — Dockerfile + `.gitlab-ci.yml` + `install_config.txt` +
  `module.yaml`, mirrored into GitLab

Its Application is generated by `app-of-apps/eda-modules-appset.yaml`, not by a file of
its own.

⚠ **NOT one of a pair — there is no `eda-xilinx-2026-1-native` app or directory.** 2026.1
is built ONLY as a container module, by this app, published as `xilinx/2026.1`. The module
is named `xilinx` rather than `vivado` because this image carries Vitis and more, not just
Vivado.

## How it runs

The tool runs **inside the shared remote-desktop pod**: a user runs `module load
xilinx/2026.1` and the desktop's podman runs this image. There is no
desktop/Guacamole/VNC here.

⚠ **Building the image does NOT make it loadable.** The module must also be REGISTERED in
the module registry, which is the broker's authority for what may run. This module
publishes to a NON-DEFAULT repo (`module.yaml`'s `image:` key), so the manifest must be
passed explicitly:

```
deployment/argocd-apps/remote-desktop/register-module.sh add xilinx 2026.1 \
  deployment/argocd-apps/eda/xilinx-2026-1/module.yaml
```

Registration is automatic on a recreate via the PostSync Job above; this is for ad-hoc work.

Requires remote-desktop `base-r14+` (`module_image()`/`image:` support in the broker, and
the `$HOME`/CWD bind in the container launcher, without which batch runs cannot do file I/O).

## Media

⚠ The 2026.1 SDI tar is **UNCOMPRESSED** (`.tar`, 105,522,216,960 bytes), unlike 2024.1's
`.tar.gz` — the extract uses `tar -xf`, NOT `-xzf`. Do not harmonise the two apps' extract
commands.

⚠ No Vitis in this image: `install_config.txt` sets `Vitis Embedded Development:0`, so
`/opt/Xilinx/2026.1/Vitis` does not exist and `xsct` is absent. Adding it is deferred; when
it lands, add `xsct` to `cli_entries` (`xsdb` is Vivado's own copy and already works).
